# 英文适配技术实现复核

日期：2026-10-17。状态：实施前技术复核保留；用户后续已批准完整实施，代码和本地验证已完成，见[实施验证记录](../validation/2026-10-17-localization.md)。下文“建议”“尚未修改”描述复核时点，不代表当前实现状态。

配套文档：[方案、文案规则与确认记录](2026-10-17-english-localization.md)。用户已同意独立设置录音识别语言；该选项不随界面语言变化。自动识别只在服务确认支持后提供。

## 1. 技术结论

建议采用“规范化 JSON 资源 + 小型纯函数运行时 + 各平台薄适配层”。复用现有设置文件、订阅退订机制与测试入口，不引入整个前端框架，不复制业务页面，不增加每条文案的 IPC 或网络请求。

翻译与业务状态分开，先建立资源和状态边界，再逐模块覆盖。NAS 同步协议不增加 locale，也不为多种语言存多份业务数据。主窗口和通知使用主进程持有的本机语言；NAS 网页使用当前访问者自己的语言，不能共用服务器全局语言变量。

## 2. 已确认的代码约束与风险

以下来自当前 dev 工作区读取；“风险”表示实施国际化时必须处理，并非声称现有产品已经发生相应故障。

| 观察位置 | 已确认事实 | 对实施的影响 |
| --- | --- | --- |
| `renderer/index.html`、`notification.html` | CSP 为 `connect-src 'none'`，脚本只允许本地来源 | 不能直接用 fetch 动态读取字典，也不能引入 CDN / 远程翻译。用本地 script 资源，保留 CSP |
| `preload.js` 与 `main.js` 窗口配置 | 两个窗口都启用 sandbox；能力通过 additionalArguments 下发，运行期另行广播 | preload 不直接 require 新的本地资源模块。首次语言用小快照下发，字典由页面本地脚本加载 |
| `main.js/readAppSettings` | 返回字段白名单；其他设置通过 read-modify-write 保存 | 新增偏好必须进入规范化读取，否则保存位置/功能等设置时可能丢失语言字段 |
| `renderer/app.js/collectLocalStorageSnapshot` | 几乎整个 LocalStorage 被采集到工作区，换目录时还可能 clear 后重载 | 桌面语言不能只放 LocalStorage；应存 app-settings，保持设备设置与工作区内容分离 |
| `main.js/publicAppSettings`、`applyAppSettings` | 目前 settings:changed 主要发给主窗口；public 结果排除加密 token | 不能直接认为通知窗口也能收到设置变化；新增语言广播覆盖两个窗口，只传非敏感语言快照 |
| `content-sync-results.json` 的读写 | 中文类型名为 key，中文结果 message 与 at 持久化 | 系统状态需要结构化与兼容读取，保留每类时间；不能把所有旧中文一律视作用户内容 |
| `taskNotificationIdentity`、`taskInbox.js` | 回退标题会进入业务结果和历史记录；摘要另有实际内容 | 在首次生成时标注系统回退原因，展示再翻译；不得把翻译标题用于去重或重写旧 AI 内容 |
| `main.js/transcription:set-config` | 使用明确字段重建设置对象；识别请求目前固定 zh | 增加识别语言必须覆盖读、校验、保存、返回与请求全过程，不只加下拉框。保存其他配置时不能清掉新字段 |
| `package.json/build.files` 与 `mac.files` | 两处都明确列举打包文件 | 新资源必须同时进入有效清单；开发目录有文件不等于 Mac / Windows 产物会包含它 |
| `build/afterPack.js` | 现有钩子执行 Mac 签名及最终校验 | 原生语言资源必须在签名前复制，不能签完再写 InfoPlist.strings |
| `scripts/build-fpk.js/preparePayload` | 临时复制 fnos，并更新共享协议与图标 | 可在临时 payload 中准备 NAS 资源，不为打包覆盖源码。不要借国际化扩改共享同步协议 |
| `fnos/app/server/gatewayHttp.js` | 静态资源限定于 app/ui 根目录和既有网关前缀 | NAS 浏览器需要的资源须进入 app/ui，不能直接向上引用服务器私有目录或扩大静态根目录 |
| `fnos/wizard/index.html` | 另有中文 HTML 安装说明 | 需核对真实调用路径；若可达，单独适配，不能认为向导 INI 会翻译这段 HTML。确认不可达后才考虑去重 |
| `website` 与 Pages 工作流 | 使用静态导出，有 basePath 和导出目录整理脚本 | 官网语言路由需静态产出，不能依赖 GitHub Pages 执行服务端语言协商或中间件 |
| `website/app/landingContent.ts` 与 README | 官网仍写“Codex、Claude 与 GPT”；README 当前通知白名单为 codex / claude / cursor | 翻译前核对中英文共同的产品事实，修正文案清单；不照抄过时能力描述，不恢复 GPT 接入 |

## 3. 推荐资源方案

### 3.1 一份来源，少量可重复生成的输出

建议新增专门的 localization 资源目录，名字在实施时确定，避免与同步协议混在一起。结构职责如下：

- `locales/zh-CN.json`、`locales/en-US.json`：规范化语义 key、完整模板、复数分支；为通用 / 桌面 / NAS / 官网划分命名空间。
- 纯函数运行时：语言映射、t、插值、复数选择、日期数字格式化，不读取 Electron、不读写文件、不拥有业务状态。
- 浏览器字典脚本：从 JSON 确定性生成普通本地 JS；不需要浏览器 fetch，加载后再运行业务脚本。
- 包资源：生成或明确维护 NAS INI、NSIS LangString、macOS InfoPlist.strings，采用各格式的专门转义。
- 官网：复用术语和通用 key，营销长文与素材保持官网命名空间；不把官网全部文本加载进每条桌面通知。

首版只有两种语言，建议页面按需加载所属模块的中英小字典，先不做复杂的异步语言包加载、LRU 缓存或在线词库。两种语言都在本机，切换不依赖网络。

为保持 `npm start` 无前端构建步骤，可提交确定性生成的少量浏览器资源，并用生成器 `--check` 校验它们与 JSON 来源一致。只编辑来源，禁止手工修改生成文件。另一种可选方案是直接编写通用 JS 资源，但必须证明 Node、浏览器和官网的模块加载方式都兼容；本次建议优先采用 JSON 来源。

### 3.2 生成器不能只是字符串替换

- 验证唯一 key、完整翻译、参数名称、复数分支和字典值类型；如使用 JSON，重复 key 必须在解析过程中检测，不能让后值悄悄覆盖前值。
- 对 JS 字符串、INI、NSIS 的 `$` / 引号 / 换行、Apple strings 的反斜线分别转义；不要共享一个万能 replace。
- 如同一句内容用于多种模板格式，生成时显式转换参数语法，校验不能存在未展开占位符。
- 输出按固定顺序、固定编码生成，不含构建时间戳；检查模式不写源码。
- 对生成产物与来源建立内容校验，而非只比较文件是否存在。
- 翻译只注入白名单文本属性；不把 HTML 模板当语言资源，也不设置事件属性或任意 URL。

## 4. 语言状态与切换

### 4.1 桌面主进程唯一持有本机偏好

推荐状态包含 `preference: system | zh-CN | en-US`、`effectiveLocale`、独立的 `formatLocale`，以及运行期递增的 revision。缺失偏好默认为 system，不需要为了升级而批量重写用户数据。

规范化逻辑提取为可单测的纯服务，纳入 readAppSettings 白名单。保存语言只接受受信主窗口与白名单枚举；保存失败时不广播成功，也不让界面长期显示与磁盘不一致的结果。主进程菜单与将来打开的原生对话框读取同一份有效语言。

创建窗口时，仿照 capabilitiesArgument 只下发非敏感的小语言快照，不传整份设置、字典、路径或任何密钥。preload 只解析、冻结并暴露快照。页面先加载本地运行时/字典，再初始化文案和业务模块。[Electron additionalArguments](https://www.electronjs.org/docs/latest/api/structures/web-preferences)

运行期复用现有订阅与退订形式：切换成功后向主窗口和通知窗口广播新快照。订阅后再读取最新状态，按 revision 丢弃旧响应，解决创建窗口与切换恰好同时发生的竞态。不能每次显示一个按钮都 invoke 一次 IPC。

system 模式在应用启动、重新激活或进入语言设置时重新检测即可；若平台提供可靠事件再订阅，不需要为这个功能新增高频轮询。手动模式不随宿主/系统事件改变。

### 4.2 更新文字，不重跑业务初始化

静态标签通过 data-i18n 与属性白名单更新；动态内容由模块独立的文字刷新方法更新。不得用重新加载页面或重建整个面板完成切换。

应保留输入框 value、密码框未保存内容、焦点与光标、草稿、分页位置、展开状态、录音 session、同步任务和通知队列。切换不能调用会重新保存内容、清空 token 输入、打开摄像头或重启录音的初始化函数。

正在显示的通知仅更新系统标签、回退标题、时间和可访问名称，再执行现有高度测量。不得调用 showNotification 重置倒计时、排队身份、悬停或 awaiting 状态。主进程仍是显示时长的唯一来源。

已经弹出的系统原生对话框按打开时的语言保留，下次打开使用新语言；不能为翻译关闭确认框、自动选择选项或重复执行 destructive action。可原地更新的应用内弹层只修改文案，不改变确认 token、覆盖预览、目标主机或操作范围。

### 4.3 NAS 是每位访问者的语言，不是服务器全局设置

NAS 网页在 system 模式依次尝试受支持的宿主语言、浏览器语言和英文回退；手动偏好只存当前浏览器，并处理存储被禁用的情况。SDK 迟到结果不能覆盖用户刚做的手动选择。

语言探测不能阻塞已有鉴权和数据加载；给宿主调用设有界超时，不可用时正常显示。是否启用 micro_app 仍需验证，不能为拿语言而在没有兼容证明时直接改网关/登录路径。

公共静态资源可复用，但服务器不写一个全局 currentLocale。前端按稳定错误码翻译；确需服务器渲染时显式传入请求级语言，不扩张现有 API 权限。语言值不能成为任意文件路径。

## 5. 旧数据和结果结构

### 5.1 系统状态逐步结构化，不全库迁移

新同步结果建议包含稳定类型 ID、结果 code、参数及原有 at / ok；保留旧 message 兼容读取。展示层把 code 转为当前语言，未知旧结果保留可核查的详情并给出本地化说明。新 code 不应直接使用可能改名的翻译 key 作为 NAS 协议。

旧中文内容类型 key 通过固定映射读取；已知系统结果模板通过来源受限的映射识别。不对用户任意文本做正则翻译，不用整体上次同步时间填充逐类时间，也不因切语言更新 at。优先读兼容、新写结构化，避免一次性改写所有历史文件。

通知的新系统回退标题保存可识别的 fallback 类型/来源/状态，实际 completionSummary 与 sessionTitle 保持原文；旧记录不能可靠区分默认标题与真实内容时保留原文。事件身份和去重不依赖任何语言资源。业务函数也不能通过比较“已完成”等显示字符串判断状态。

### 5.2 默认分类与用户内容

已有自定义分类、笔记标题、录音标题不改写。新用户默认名应有可识别的系统来源，显示时可翻译；必须同时考虑 NAS 其他设备仍可读取、用户一旦改名就转为用户内容等情况。若没有兼容实现，不为英文 UI 批量迁移分类数据。

旧的系统默认名可能留有中文，需要在验收中作为兼容例外列出；不能声称所有历史数据也应变成英文。数据协议和同步实体 ID 不随显示语言改变。

## 6. 录音与智能命名

界面 locale 与 transcriptionLanguage 独立。建议首版识别偏好作为本机设置，不额外扩 NAS 的 AI 配置协议；如需多机同步该偏好，应另列为功能扩展。

读配置、保存配置、公开配置、浏览器 SpeechRecognition、云转写 session.update 均要覆盖同一个规范化枚举，并按不同后端参数格式映射。客户端选项不代表后端支持，英文/自动/中英混合的可用性需逐一核对。

本轮已核对百炼官方客户端事件文档：`session.input_audio_transcription.language` 明确列出 `zh` 与 `en`，中文/英文参数已有文档依据；尚未发送真实音频验证所配置区域和账号的效果。不据此推断自动识别的参数应为字符串 `auto`，也不把其他实时翻译模型的说明直接套用到当前 ASR 模型。[中文 API 文档](https://help.aliyun.com/zh/model-studio/qwen-asr-realtime-client-events)、[国际 API 文档](https://www.alibabacloud.com/help/en/model-studio/qwen-asr-realtime-client-events)

录音启动时把识别语言固化到 session，重连沿用同一语言。录音期间改设置对下一次录音生效，并有明确提示，避免强行重启导致断音或全文重写。已有用户继续保持原中文识别；新安装默认识别语言规则在服务能力核对时定稿，不能从“界面跟随系统”推导出录音必须随界面自动变化。

新增语言字段后，保存 API Key / 地区 / 模型时必须保留它，修改语言也不能清空现有 Key。云端 region 与 endpoint 完全沿用原设置。普通资料备份与 NAS 同步的内容范围保持原样。

智能命名按转写内容语言生成，不按 UI locale 强制输出；混合语言优先遵循原内容，不为自动判定新增在线翻译请求。历史命名保持原文。

## 7. 各平台资源、打包与官网

### Windows

仅声明 en_US / zh_CN，默认不弹语言选择器；应用资源与安装器资源各走正确格式。安装与卸载都要按当前系统显示语言判定，不能读地区格式、应用手动偏好或缓存的安装语言。

使用现有 assisted installer 和受支持初始化钩子，不复制整份第三方 NSIS 模板。注意钩子执行顺序，必须在首个自定义提示前选好语言。测试“中文安装 → 英文系统卸载”与反向组合，不以配置项存在就判定通过。保留目录选择、快捷方式与数据保留默认值。[NSIS 官方自定义入口](https://www.electron.build/docs/nsis/)

### macOS

本地化用途说明随 .app 放入正确的语言资源目录，使用 InfoPlist.strings；语言声明与应用语言支持一致。沿用现有 afterPack 签名流程，复制资源必须在签名前完成，后续检查只读。不能为了“只有中英”删除 Electron / 系统所需的其他运行时资源。[Apple 本地化资源说明](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPInternational/LocalizingYourApp/LocalizingYourApp.html)

打包清单有全局与 Mac 两处，资源核对必须覆盖有效合并结果。可增加一个资源清单校验，暂不为此重构所有现有打包配置。

### NAS

生成包 INI 与浏览器资源后，在临时 payload 中汇集，沿用当前原子清理方式；不要调用会更新源码的 prepare-only 路径作为普通校验。包内未展开引用、语言文件一致性和安全确认内容列入检查。

独立 HTML 安装说明先确认是否真实可达，再决定本地脚本适配或与现有向导文案复用。没有调用证据时不删除文件，也不假定它已被官方 INI 自动本地化。

国内 fnpack 与国际 fygopack 只在构建适配层区分，尽量共用应用 payload。依赖应用与最低系统版本需要实际国际环境验证；这些工作不应被误算为已经通过的双语测试。

### 官网

建议保留原中文入口，增加可直接访问的 /en/ 静态入口，共用 React 组件和数据结构，分别产出 lang、SEO、分享信息与语言切换链接。无需复制整套页面或引入新的站点框架。

不能仅用浏览器本地切字替代英文独立页面，否则分享和搜索抓取仍可能拿到中文。GitHub Pages 没有本项目的服务端语言协商路径；首版不依赖请求头中间件。

新增路由时必须核对 prepare-pages-output 的目录整理逻辑、/Pome-Panel 基础路径、刷新深链接、_next 资源与英文静态 HTML 都保留。现有代码有删除嵌套输出目录的步骤，应验证不会误删新页面；这是新增路由的风险检查，不是已确认现有官网故障。

Pages 当前工作流只监听 website/** 和自身配置；若官网导入仓库根部共用字典，必须补充路径触发条件及实际依赖的校验入口，否则只改共用文案可能不重新部署官网。下载平台识别与 releases/latest 解析不随语言变化。

## 8. 性能与测试可以怎样简化

- 缓存 Intl.DateTimeFormat / NumberFormat / PluralRules 等少量实例，按语言/格式/时区区分；翻译不读磁盘、不走 IPC，切换时失效相关缓存即可。
- 不新增高频 DOM 全量扫描、MutationObserver 自动翻译或轮询宿主语言。静态节点初次登记，后续刷新已登记文案；新弹层由所属模块登记。
- 只在显示层截断。若必须按字符截断，避免切断 emoji / 组合字符；可优先用 CSS 省略，减少额外算法。不能降低现有摘要存储限额来适应英文。
- 资源单测快速覆盖全部 key；已有中文业务测试保留，新纯逻辑测试用显式 locale，减少依赖测试机系统语言。
- 不必把全部 Electron 测试机械重复两遍。保留完整现有回归，额外挑选语言启动/切换、NAS 异常、通知、录音配置与长文案布局做双语测试。
- 资源生成、NAS INI / 向导占位符与临时 payload 检查可用模拟构建器完成，无需真打包；现有 fpk-build.test.js 已有注入 run 的测试形式可复用。
- 安装产物的资源清单、签名与真实安装语言是另一层验证，需要用户明确授权打包后执行；源码测试不能替代实机安装。
- 官网单独执行现有 test / lint；正式构建仍按用户授权，不在本轮触发。未支持的 locale、宿主失效、存储不可用和资源缺失均要验证能退回可用界面。

## 9. 推荐实施顺序与完成证据

| 步骤 | 交付内容 | 进入下一步的条件 |
| --- | --- | --- |
| T1 | 文案清单、确认的术语、规范资源、生成器检查 | 已知用户系统文案都有来源或已审核例外，资源一致性通过 |
| T2 | 本机偏好、启动快照、切换广播与纯函数 | 保存其他设置不丢语言；两个窗口不混用状态；重启正确 |
| T3 | NAS 设置与网页、结构化结果兼容、完整异常提示 | 配对/暂停/恢复等主路径中英可操作，旧时间与用户内容不改 |
| T4 | 全部桌面模块、通知、录音独立语言 | 切换不丢草稿、不重启录音、不重置通知，四档布局正确 |
| T5 | 安装资源、官网与用户文档 | 源码和模拟 payload 检查通过，公开产品事实与 README 一致 |
| T6 | 授权后的实际产物和实机验收 | NAS / Mac / Windows 安装语言及资源、签名、中文回归有独立证据 |

每个步骤都在 dev 做局部可审阅变更，保持现有测试可运行，不以“大量替换完再统一修复”作为工作方式。提交、推送、打包和发布仍需按用户当前授权执行。

## 10. 结论分级

**建议作为实施必需项**：轻量本地资源、严格资源生成检查、设置白名单与跨窗口状态、旧系统结果兼容、录音 session 语言固定、两处打包清单、签名前写入 Mac 资源、安装/卸载语言交叉验证、官网静态路由与工作流触发检查。

**可选优化**：伪本地化、关键截图自动差异检查、更细的资源按模块分包。首版不需要在线翻译、翻译管理 SaaS、重量级动态加载、修改 NAS 协议或迁移全部历史数据。

**仍需能力/环境验证**：转写区域/账号的实际结果、自动识别参数与混合语言效果、国际 NAS SDK/网关兼容、实际包工具与依赖目录、Windows 卸载语言行为、原生授权窗口的实际语言。这些不等于需要改变已确认的产品范围，也不应在未验证前承诺完成。


## 实施落点

- JSON 是双语文案源；生成脚本同时产出本地浏览器资源、NAS INI、NSIS LangString、macOS InfoPlist.strings 和官网使用的字典子集。桌面无新增构建链，CSP 不变。
- 桌面语言存 app-settings，preload 仅带小快照，主窗口/通知/菜单由主进程统一广播。语言切换不重置倒计时、页码、草稿或用户原文。
- NAS 增加 micro_app=true，随包携带校验过的官方 @trimjs/web-app 0.5.0 ESM，只调用 getPlatformConfig 和支持的 os/language。宿主读取有 1.5 秒超时，旧环境/独立网页回退浏览器；不引入服务器全局 locale，不调用凭据 API。
- 录音识别采用官方已明确的 zh/en，配置与界面语言独立；开始时冻结，重连沿用。未添加未经证实的 auto 参数，未用真实音频/账号验证云端效果。
- 同步旧中文类型键、稳定事件身份和冲突哈希保留；新增回退标题标记和系统消息描述仅用于展示。明确生成的冲突后缀可本地化，底层历史标题不重写。
- 官网根路径保留中文，/en/ 输出英文，并使用实际英文界面截图。修正静态尾斜杠导出和子路径元信息重复前缀，构建产物可验证。
- 原生安装器按资源/配置与测试验证；没有执行安装包构建、签名、发布或真实安装，仍需后续授权的 Windows/NAS 实机验收。
