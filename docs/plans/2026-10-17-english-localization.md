# Pome Panel 英文适配方案与文案规则

日期：2026-10-17。状态：用户已批准实施；中英双语代码、资源、官网与面向用户文档已在 dev 实现，验证结果和实机边界见[实施验证记录](../validation/2026-10-17-localization.md)。以下现状分析保留为实施前依据；当前产品行为以 README 为准。

## 1. 首版目标与边界

首版提供简体中文 `zh-CN`、英语 `en-US`，覆盖 NAS 安装配置、NAS 网页、macOS / Windows 桌面、系统菜单与通知。保留中文体验，同一份业务代码通过本地语言资源切换，不复制一套英文界面。

英文适配应完成四件事：语言选择与回退、全部系统文案翻译、日期数字与布局适配、双语回归。只添加 NAS 的 `i18n/en-US` 文件不能完成整个产品的适配。

不因语言切换改变 NAS 协议、数据结构、API 区域、登录凭据、默认组件布局或已有通知行为。用户内容保持原文，不调用在线翻译服务。

按“所有文案适配英文”的要求，将官网、安装/配对/权限帮助和下载引导也纳入范围。文档以是否面向用户为界：对用户展示的文档与更新说明需翻译，历史文档若仍面向用户也不因其年代而排除；内部研发计划、ADR、调试笔记和测试数据不翻译。判断依据是用途，不能仅因开发文档在公开仓库就将其归入用户帮助。无需为了首版同时适配所有 FygoOS 系统语言。

## 3. 语言选择规则

设置增加“语言 / Language”，提供“跟随系统 / System”“简体中文”“English”。全新安装 NAS / macOS / Windows 均默认“跟随系统”，不是固定中文或固定英文；首次使用 NAS 网页在宿主内跟随宿主语言，独立访问按浏览器语言回退。已有手动偏好不被升级安装覆盖。该选项是本机偏好，不随 NAS 同步；NAS 网页的手动选择只保存在当前浏览器，不改变其他设备。

| 环境 | 自动模式的优先级 |
| --- | --- |
| 桌面 | 主进程读取的系统语言 → 语言映射 → 英文回退 |
| NAS 宿主内网页 | 宿主 SDK 提供的当前界面语言 → 浏览器语言 → 英文回退 |
| 独立打开的 NAS 网页 | 浏览器语言列表 → 英文回退 |

手动选择始终优先于自动检测。首版明确识别 `zh-CN` / `zh-Hans` 和英语变体；未支持的语言回退为英语。是否把其他中文地区标签映射为简体中文应明确记录，不能宣称已经支持繁体中文。

桌面自动检测优先采用 `app.getPreferredSystemLanguages()`，而不是用国家/地区或 `getLocale()` 代替用户语言。界面语言与地区格式设置独立。[Electron 语言 API](https://www.electronjs.org/docs/latest/api/app#appgetpreferredsystemlanguages)

语言偏好与最终生效语言分开保存，例如偏好为 `system`，实际生效为 `en-US`。英文资源缺项时生产环境回退英文通用提示，不能显示资源 key、`undefined` 或空按钮；缺项和占位符不一致必须在 CI 失败。

桌面通过 `preload.js` 的安全桥接下发语言。主窗口、通知窗口、菜单和后续打开的对话框使用同一份语言状态；渲染层不直接引用 Electron。切换时保留输入草稿、光标与选择，不重置业务数据；初始化失败也要显示可用界面。

NAS 若使用官方 SDK，读取 `getPlatformConfig().language`。接入前需评估当前 iframe 模式和 `micro_app=true` 要求；不能只引入 SDK 就假定可用。宿主接口不可用或超时，应回退浏览器语言。只有受支持的嵌入 Web 环境订阅 `os/language`，独立网页和其他环境不能依赖该事件。[官方调用说明](https://developer.fygonas.com/api/calling/)、[平台配置](https://developer.fygonas.com/api/platform-config/)

仅获取前端语言无需额外申请后端系统权限；不得向网页暴露 `TRIM_API_TOKEN`。生命周期脚本可按官方 `TRIM_SYS_LANGUAGE` 选择自身提示语言，该环境变量不应替代每位网页用户的界面语言。

### 3.1 安装、升级与卸载：仅中英，跟随系统

这是已明确的需求，不作为可选优化：

| 平台 | 规则与实现约束 |
| --- | --- |
| Windows | NSIS 资源限定 `en_US`、`zh_CN`，英文为默认回退；`displayLanguageSelector=false`，不出现语言选择弹窗。标准页和自定义页使用相同语言，`LangString` 覆盖欢迎、目录、安装、完成、卸载和失败提示。安装和卸载启动时都按当前 Windows 显示语言判定，不沿用应用手动设置或旧安装语言。若模板默认行为不满足卸载重新判定，使用受支持的初始化钩子补齐，并在任何自定义提示出现前完成。 |
| NAS | 仅提供 `en-US` 与 `zh-CN` 包语言文件，安装/配置/升级/卸载均走宿主当前语言和官方回退机制，不能由网页手动选择反向改变。脚本错误也覆盖两种语言。 |
| macOS | 当前是 DMG 安装路径，没有 NSIS 式安装/卸载向导；Finder、系统授权框的系统部分由 macOS 控制。我们提供的 DMG 引导及权限用途说明做中英资源，按系统/应用原生语言协商显示，不另造卸载向导。 |

Windows 安装目录、桌面/开始菜单快捷方式和卸载保留数据的既有行为保持不变。NAS 卸载保留 `keep` / `delete` 字段值与默认保留选择，只翻译标签和说明；明确删除的是应用数据文件，不能弱化成“仅删除设置”。

安装器“跟随系统”与应用内手动切换是两套规则：应用切成英文，中文系统下重新安装/卸载仍按中文；系统改成英文后卸载应显示英文。NAS 其他语言系统是否实际回退英文需安装验证，不能仅靠存在 en-US 文件推断所有版本的宿主行为。[electron-builder NSIS 选项](https://www.electron.build/docs/nsis/)

## 4. 资源组织与代码规则

### 4.1 两种资源，各自负责对应界面

**NAS 包资源**使用官方 extensionless INI：`fnos/i18n/en-US`、`fnos/i18n/zh-CN`。已有 `i18n/` 时，官方要求提供 `en-US`；所有已提供语言的 section / key 必须一致。manifest、入口和向导使用 `${section.key}` 引用。[官方国际化规范](https://developer.fygonas.com/cn/docs/core-concepts/i18n/)

**应用资源**为桌面与 NAS 网页提供轻量字典和翻译/格式化函数。优先使用能被当前 Node 与无构建步骤的浏览器代码加载的资源形式；不为翻译新增整个桌面前端构建链。共用同一个术语表和通用文案，平台差异保留独立 key。NAS 包 INI 可由明确的构建步骤生成或维护，但不得假定包资源会自动翻译 HTML/JS。

主进程、渲染层和 NAS 页面的资源实际进入各自打包清单；不能开发时可读、安装后找不到。具体目录名在实施时统一，不把本方案中的示例当成已有模块。

### 4.2 Key 与模板

- 使用语义 key，例如 `common.actions.sync`、`nas.pair.invalidCode`、`notifications.fallback.completed`；不要用整句中文当 key。
- 一句完整信息对应一个模板，使用具名参数，如 `Configuration saved. Quit and reopen {app} to apply.`；不要拼接“来源 + 后半句”来组成英语。
- 各语言的 key、参数名称、复数分支保持一致。根据 `Intl.PluralRules` 或等价的 one / other 分支处理复数，不拼接 `s`。
- 翻译值默认作为纯文本渲染，插值使用 `textContent` 或等价转义；项目名、路径和服务端信息不能通过翻译模板变成 HTML 注入。
- 错误码、状态枚举和事件身份保持稳定，翻译发生在展示层。新文案优先利用已有结构化结果；不得仅为翻译改变 NAS 端协议。
- 用户可见错误按已知错误码翻译；未知错误给出可操作的通用文案及安全的诊断入口，不能把 token、私密路径或原始响应直接塞进提示。

### 4.3 数据兼容

- 保持 LocalStorage 键、待办 `P0`–`P3`、来源 ID、状态枚举、集合名、接口字段、路径、端口和应用 ID 不变。
- 笔记、待办、项目名、会话名、AI 实际摘要、录音转写、用户命名分类与城市原始信息不自动翻译。
- 旧记录中已经保存的中文标题保持原文。仅对能明确识别为系统生成的默认标题在展示时翻译；必要时为新记录保存模板标记和参数，不靠正则猜测旧内容。
- 通知去重与排序不依赖翻译后的标题，切换语言不能重复提醒、清空未读或更改事件 ID。
- 新用户的默认分类名可本地化；已有分类若无法区分系统默认与用户自定义，保留原值。不能因为名字恰好是中文默认值就覆盖用户数据或批量触发 NAS 同步。
- 语言偏好不进入普通内容同步；保持普通备份不覆盖系统设置的现有约定。
- `content-sync-results.json` 当前用中文内容类型作 key，并持久化中文结果 message。此处是系统状态，不能按“用户原文保留”直接留下中文：增加稳定的类型/结果标记，读取时兼容旧中文 key，已知旧结果按明确映射显示，保留每行 `at`。不能全文件字符串替换或据此更改同步协议；未知旧详情保留诊断信息并给出本地化说明。
- `humanizeSyncError` 当前可能直接返回上游中文 `message`。英文路径必须优先使用已有错误码和已知来源的结构化结果，补足已知旧消息兼容映射，避免字典已翻译而错误仍漏出中文。未知来源信息与系统提示分开展示，不能吞掉故障原因。

## 5. 英文文案规范

### 5.1 基本风格

采用美式英语、sentence case。按钮使用直接动词，例如 `Save`、`Sync`、`Pair`、`Retry`、`Open settings`；状态使用状态表达，例如 `Syncing…`、`Paired`、`Sync paused`。避免每个提示都加 `Please`，但校验提示仍需明确说明下一步。

进行中的状态使用单个省略号 `…`。产品名保持官方写法：Pome Panel、Codex、Claude Code、Cursor、Grok、Antigravity、GitHub Copilot、Manus；不因翻译增加、删除或声称支持某个来源。NAS 中英文均可保留 `NAS`。品牌名、模型名、文件名、命令、URL 和路径不翻译。

成功文案只陈述已经完成的动作：“配置已保存”不能写成“已经生效”；“已配对”不能写成“全部同步完成”；“已打开软件”不能声称“已定位到具体对话”。

失败文案说明对象、原因和可用的下一步。只在确实检测到未安装时使用 `not found`；不能把网络超时、令牌失效、缺权限都归为“无法连接”或“窗口已关闭”。

### 5.2 统一术语

| 中文概念 | 英文约定 | 使用说明 |
| --- | --- | --- |
| 首页 | Home | 页面名 |
| 待办 | Tasks | 单项为 task；截止提醒不叫 AI completion |
| 笔记 / 链接 / 录制 | Notes / Links / Recordings | 页面名，使用复数 |
| 剪贴板 / 常用指令 | Clipboard / Commands | 不把指令翻成 chat instructions |
| 密钥模块 | Credentials | 当前同时包含账号、密码与 API Key；具体字段仍按实际名称显示 |
| API Key | API key | 不与设备令牌混用 |
| 设备令牌 | Device token | NAS 配对身份 |
| 账号同步密钥 | Sync encryption key | 加密用途，不能简称为登录 token |
| AI 剩余额度 | AI quota | 数值旁明确 `Remaining` 或 `Used`；不能改换含义 |
| AI 完成 | AI activity | 包含完成、失败、待确认等记录，标题不暗示全为成功 |
| NAS 同步 | NAS sync | 卡片标题 |
| 配对 / 已配对 | Pair / Paired | 动作与状态区分 |
| 未配对 / 同步中 | Not paired / Syncing… | 未配对不写成网络离线 |
| 同步已暂停 | Sync paused | 保留暂停原因与 recovery 入口 |
| 重新配对 | Pair again | 不写成可能误导为账号登录的 Sign in |
| 恢复快照 | Restore snapshot | 确认中说明覆盖对象和影响 |
| 刷新 / 重试 | Refresh / Retry | 主动更新数据与重做失败操作区分 |

### 5.3 关键文案示例

示例约定语义与风格，具体错误触发条件沿用现有代码，不新增成功判定或协议状态。

| 场景 | 英文文案 |
| --- | --- |
| Codex / Cursor 接入成功、配置确实有写入 | `Configuration saved. Quit {app} completely, then reopen it to apply the changes.` |
| Claude Code 接入成功 | `Configuration saved. Exit Claude Code, then start it again to apply the changes.`；不要求退出整个终端 |
| 未配对的同步入口 | `Pair this device before syncing.` |
| 配对码为空 / 格式不对 | `Enter a pairing code.` / `Enter a 6-digit pairing code.` |
| 设备令牌丢失 | `A sync address is saved on this device, but its device token is missing. Pair again to resume syncing.` |
| 同步已暂停的覆盖预览入口 | `Preview replacing NAS data with local data` |
| 明文 HTTP 确认标题 / 操作 | `Pair over unencrypted HTTP?` / `Pair anyway` / `Cancel` |
| 协议不兼容 | 按现有错误指明需要更新的一端，例如 `Sync protocol incompatible. Update the NAS companion.`；不能猜测更新方向 |
| 成功通知无摘要 | `Codex task completed`；其他来源使用同类完整模板 |
| 通知副标题 | `{source} · {project}`；无项目时只显示 `{source}` |
| 失败 / 等待确认 | `Task failed` / `Awaiting confirmation`；有实际摘要时优先保留摘要 |
| 待办即将截止 | `Due within 1 hour` |
| 相对时间 | `Just now` / `1 minute ago` / `{count} minutes ago` |
| 打开来源软件 | `Open Codex` / `Open Cursor` / `Open terminal` |
| 确认没有找到 Codex | `Codex isn't installed.`；检测结果不明确时使用 `Couldn't open Codex.` 并保留已知原因 |
| 有缓存、刷新失败 | `Refresh failed · Showing cached data`，同时保留原数据时间 |
| 重置时间已过但数据没更新 | `Refresh needed`；不能显示为额度已恢复 |
| 无额度数据 | 沿用缺省符号并显示无数据状态，不能补成 `100%` |
| NAS 卸载保留 / 删除选项 | `Keep app data` / `Delete all app data (cannot be undone)` |
| NAS 卸载删除说明 | `All app data files will be permanently deleted. This action cannot be undone.`；按实际范围补充说明，不删除“不可恢复”的含义 |

HTTP、证书、覆盖、回退和恢复确认必须翻译完整正文，保留风险、目标主机/端口、影响范围与取消操作。不能只翻译按钮，也不能用 `Continue` 替代明确的破坏性动作。证书信任仍限定原主机、端口和证书，不扩大授权。

### 5.4 内容与系统标签分离

实际 AI 摘要是什么语言，就按原语言显示。系统只翻译来源名以外的标签、状态、回退标题、相对时间和错误。英文系统标签旁出现中文用户内容是正常情况，不能通过覆盖摘要来“清除中文”。

同理，用户自定义标题不随语言切换改名。新生成的系统默认名称需要携带可识别的来源；已经落盘且无法区分的历史文字保留原文。

### 5.5 时间、数字与录音

- 日期、时间、数字统一经格式化入口处理，使用生效 locale。尊重可获得的 12/24 小时和日期格式偏好，不把所有英文用户强制改为 12 小时制。
- 语言与时区独立：日出日落继续使用城市的坐标、日期和 IANA 时区；切英文不能把城市时区改成设备时区或 UTC。
- 百分比、额度单位和金额保持原始语义与币种；缺失值、过期值、缓存值仍需可区分。
- 相对时间继续按事件真实发生时间计算；排队不刷新时间戳，未来时间保留现有合理钳制策略。复数至少覆盖 0、1、2 与较大数值。
- 详情每类同步时间来自该类实际结果，不用整体时间填充缺失值。
- 单独设计录音语言设置；保留已有识别行为，确认服务支持后再开放英文或自动识别。界面语言不能自动改变用户的 API 区域、Key、模型、计费端点或录音内容。智能命名提示词的输出语言也应明确决定，不能把界面英文等同于翻译转写全文。

录音语言的通俗解释：**界面语言决定按钮显示中文还是英文；识别语言告诉转写服务录音中主要说的是什么语言。** 例如界面使用 English，但用户在录中文会议，仍应按中文识别；改成中文界面也不能把已经选择的英文识别悄悄切回中文。这不是把录音翻译成另一种语言，而是帮助服务准确识别原话。

入口放在现有转写设置中，名称“识别语言 / Transcription language”，先提供服务确实支持的中文和英文。已有用户保留原中文识别行为，不因界面语言迁移而修改；服务是否支持中英混合或自动识别需核对后决定，不预先承诺“自动”。用户已在解释后同意独立设置方案，但明确要求先不改代码，继续梳理技术实现。

智能命名已按用户意见确定：新生成标题跟随原始转写内容的语言，历史名称不改；不因为界面为英文就强制把中文录音命名成英文。

### 5.6 布局与可访问性

- 为英语更长的按钮和状态预留宽度，优先允许必要换行或调整内部弹性布局，不整体缩小字号、不扩大固定窗口来掩盖溢出。
- 首页 mini / small / medium / large 全部检查；mini 不显示分页的现有规则保持不变，条数和请求不因翻译改变。
- 顶部通知维持现有平台尺寸和最多两行标题。摘要仅展示层截断，保留完整内容读取入口；等待确认不自动关闭，悬停与倒计时行为保持原样。
- 安全说明、错误正文和关键操作不能省略到无法理解；短按钮仍需完整的可访问名称。
- 同步翻译 `title`、`placeholder`、`aria-label`、图片替代文字、状态提示及原生系统菜单；设置 HTML `lang`。语言选择器保留 `English` 与“简体中文”各自的自称。
- macOS 权限用途说明通过两种语言的原生资源（例如 `InfoPlist.strings`）随包提供，检查摄像头、麦克风、自动化和局域网四项。系统自身的按钮和安全提示由操作系统提供，不能承诺用应用内手动语言覆盖所有系统窗口。
- 城市名优先用已有英文数据；缺少英文名时保留原名或经审核的别名，不在运行时自动音译。搜索支持现有名称与已收录别名，城市 ID、经纬度和时区不变。
- 英文官网的 SEO 标题、description、HTML lang、分享文案、下载失败/加载状态一并处理。图片、视频若含产品文字，需替换为对应语言截图或明确作为原文演示；不能靠翻译 TSX 文本就声称所有素材已经英文。

## 6. 分阶段实施

### 阶段 A：语言基础与文案清单

1. 盘点静态 HTML、动态 JS、主进程菜单/对话框、安装器和脚本输出，标注系统文案、用户数据、品牌名三类。
2. 建立双语资源、术语表、插值/复数/格式化工具、主进程语言状态与安全 IPC。
3. 增加语言选择和回退；用“设置 → NAS 同步 → 一条 AI 通知”跑通跨窗口切换。
4. 增加 key / 参数完整性检查。扫描结果允许有审核过的中文用户数据、城市数据和中文测试期望，不能机械禁止一切汉字。
5. 导出可审阅的逐条文案清单，至少含 key、原文件/位置、中文、英文、触发条件、长度/布局约束、审核状态；每项已发现的产品系统文案必须进入资源或有明确的例外原因。示例表复核不等同于全量文案完成审核。

交付门槛：同一操作中主窗口、气泡与原生确认框不混用系统文案语言；刷新或重启后偏好正确保留。

### 阶段 B：NAS 英文路径

1. 补齐 package INI 引用，翻译实际向导和生命周期错误。
2. 翻译 NAS 网页全部页面、配对/权限错误和空态；实现宿主语言检测及独立网页回退。
3. 将需要的字典打入 NAS 包；核对国内包构建工具对新增引用的支持。
4. 为国际版规划 `fygopack` 构建目标，与现有国内目标分开验证；保持 app ID、网关、权限和数据路径。不能未验证就承诺同一个 FPK 对所有国内旧系统与国际系统通用。

交付门槛：英文系统下从安装、打开网页到配对错误/成功均可理解；中文路径继续可用。国际系统依赖目录、实际最低版本及升级兼容需实机确认。

### 阶段 C：桌面完整覆盖

1. 翻译所有页面、组件、设置、表单、备份和恢复路径；保持现有数据与平台能力开关。
2. 翻译 AI 额度/接入/收件箱/顶部通知，确保真实摘要与系统标签分离。
3. 翻译 macOS 菜单/对话框、Windows 托盘和 NSIS 自定义页。安装器使用相应语言资源，不能安装器为英文而自定义段落仍为中文；安装器语言不覆盖用户保存的应用偏好。
4. 处理日期数字、城市展示、录音语言的独立设置与英文布局。
5. 完成官网和当前用户帮助的双语覆盖，保持下载按钮的平台判断、版本解析与链接行为。

交付门槛：中文和英文各有一轮完整桌面主路径回归，macOS 与 Windows 分别验证，不能用 Mac 测试替代 Windows 真机。

### 阶段 D：回归与发布准备

1. 完成下表自动测试和截图验收，更新英文安装/配对/权限说明。
2. 经用户明确要求再打包，检查资源完整、安装器语言与首次启动；测试实际国际 NAS 包安装/升级。
3. 全部开发仍在 dev。仅在用户要求发布时联动版本、CHANGELOG、README 和官网入口，通过 dev → main 发布流程。

不建议先只翻译首页就标记为“支持英文”：配对失败、权限、同步暂停与恢复恰好是用户最需要说明的地方，首版必须一并覆盖。

## 9. 二次复核结论

原方案的英语示例整体语义正确，但尚不能称为全项目文案审核完成。此次复核明确修正和补齐：

| 发现 | 处理 |
| --- | --- |
| “Quit {app} completely”不宜不加区分用于 Claude Code | 区分桌面应用重开与 Claude Code 会话退出重启，不要求用户退出整个终端 |
| “to apply”缺少明确对象 | 完整提示统一为“to apply the changes”；短空间优先换行，不删除重开要求 |
| “Codex not found”可能混淆没安装与启动失败 | 只有可靠确认没安装才写“isn't installed”；其他失败写“Couldn't open…”并保留原因 |
| 待办和 AI 任务都可能叫 task | 用页面/模块上下文区分，任务真实标题不改；AI activity 已获用户确认 |
| 密钥模块包含账号和密码 | Credentials 已获用户确认；具体 API key / device token / encryption key 各用自己的名称 |
| 卸载原文“设置”与实际删除范围不够一致 | 中英文都明确 app data，保留不可恢复警告及默认保留行为 |
| 当前存盘的同步详情和上游 message 为中文 | 增加兼容读取和按错误码展示的实施项，不能只替换界面字面量 |
| 主进程、OS 权限、安装器、素材和官网容易遗漏 | 全部加入覆盖清单；OS 自身提供的文字不视作应用可任意改写的资源 |

“所有文案”指所有应用提供且用户可见的系统文案；第三方错误原文、用户数据、历史内容和系统自身文案分别按来源处理。交付时需提供未翻译项/例外清单，不以汉字扫描为零伪装覆盖完成。
