# 收件箱去重、损坏恢复与 NAS 容量改造

2026-10-13。本次用户明确批准替换原冻结说明中的时间窗口去重和“首轮不清理 NAS 快照”边界。其他页面结构、未读保留、本机优先和暂停同步约定继续有效。README 是当前产品行为准绳。

## 完成事件身份

- 来源可提供时采用 `event_id` / `eventId` / `event-id`。否则必须同时提供任务/会话身份，用来源、任务/会话身份与 `turn_id` / 回合序号或 `completed_at` 生成确定性 SHA-256 身份。来源参与命名空间，来源间同 ID 不串联。
- 收件箱入口使用来源字段生成身份，不用当前接收时间伪装完成身份。只有任务/会话 ID 或文本的请求无法区分延迟重试与后续同文本完成，返回 HTTP 422 `completion_identity_required`，不生成记录或通知。
- Codex 原始字段透传；Claude 从主线助手消息读取 UUID/消息 ID、来源时间，重复转发沿用同一身份；新消息即使文本相同也有独立身份。GPT 接入方必须提供上述字段之一。
- 记录、去重信息、首次已读时间一起持久化。延迟重投和重启重投不新增、不重新变未读、不更新接收时间；同一任务下一次真实完成正常接收。
- 已读首次标记后 30 天删除记录及其去重键；未读记录继续保留，所需去重键也继续保留。到期清理后不承诺对更早的事件永久去重。旧版历史记录继续保留，不凭旧接收时间推断缺失的来源完成身份。

## 用户确认的损坏恢复

收件箱显示暂停接收原因、原文件路径以及“备份损坏文件并重建”。主进程再次检查错误状态，确认弹窗显示完整备份目标路径和历史、已读及去重信息可能无法恢复的影响。默认选取消，取消不写文件、不解除暂停。

实现先将精确原始字节保存到同目录 `task-inbox.json.corrupt-时间戳-UUID`，持久化并读回核验，再原子替换为新空收件箱。这让备份与重新建立收件箱之间始终保留原文件；备份失败不能清空，替换失败仍有原始副本。确认期间原文件内容变化要求重新确认。成功后新完成事件正常接收，重启仍可读；损坏备份不自动删除。

只改文件属性或原子替换为相同字节不会误暂停；真实内容变化仍停止使用旧缓存并重新读取，不静默覆盖外部资料。

## NAS 容量与协议

默认保留期 90 天，回退窗口 30 天，可用 `FNOS_SYNC_RETENTION_DAYS` 和 `FNOS_ROLLBACK_WINDOW_DAYS` 设置正数天数。处理请求时距上次检查一小时，或累计 256 个事务，触发检查点清理；NAS 空闲且无请求时没有持续写盘。

1. 设备再次请求某游标表示上次对应内容已应用。按账户、未撤销设备、各同步集合记确认水位；全局拉取也可确认全局水位。只有所有已知设备确认过的连续日志前缀可以提前截断。未确认部分至少保留 90 天，超期才推进 `logFloor`。
2. 低于 `logFloor` 的游标返回 409 `full_resync_required`。全量拉取采用绑定账户/设备/集合的冻结内容快照，500 条分页，30 分钟有效；返回期间有新写入不改变快照。完成后游标定位到快照版本，再增量追后续版本。失败、重启或快照过期时重新全量拉取，不能提交部分全量结果。
3. 幂等结果以服务器接收时间保留 90 天；清理推进永久的 `mutationFloor`。缺失去重结果且基线低于截断/幂等水位或高于当前服务器版本的请求返回 409 `mutation_expired_resync_required`，整批不执行。不能仅相信客户端自己填写的时间。仍保留的去重结果可返回原接受结果，不重复执行。
4. 桌面全量拉取全部验证后才应用。待办在 SQLite 事务中替换远端基线、生成新请求身份继续本机待发送修改，远端删除取消旧更新；笔记继续保留离线修改的冲突版本。工作区索引中远端已不存在的条目按删除结算，不复活已删除内容。
5. 最近一次已提交覆盖的快照始终保护；回退窗口内的已提交快照、24 小时有效期内的准备/暂存操作也保护。其他快照按 90 天保留期删除。最近一次覆盖由独立操作标识定位，空覆盖即使没有递增服务器版本也不会误选旧快照。过期准备操作必须重新预览、确认和创建操作；客户端保持暂停并换新操作身份。回退仍校验当前 NAS 未发生后续修改。
6. 业务日志截断、幂等清理、快照清理与水位发布通过同一原子检查点完成。检查点 fsync、读回校验及原子改名成功后才删除覆盖的事务文件；失败从已提交存储重新加载。改名前中断保留旧状态，改名后中断按新检查点忽略已覆盖日志，不重新回放旧业务。

内部检查点升级 v3，读取 v1/v2 并连同尚未合并的事务升级；旧服务无法读取 v3，不能直接降级。HTTP 仍使用 v1 地址和基础 schema，增加明确错误和全量模式；桌面与 NAS 需配套升级。普通桌面 ZIP 备份仍是 v1。NAS 备份必须同时保留检查点、事务目录与 `server-id`。

实际业务资料、删除标记和未读收件箱不按缓存规则清理。本次没有承诺全部账户资料的总容量硬上限，也没有新增快照管理页面。
