# 当前窗口：身份、聚焦与列表布局

日期：2026-10-29，分支 `dev`。保留之前工作区的其他改动；未提交、推送、打包或发布。

## 判断与证据边界

1. **已确认的代码错误**：旧扫描来自 CoreGraphics 全部图形窗口表，记录的 `windowIndex` 是全系统序号；聚焦却用它索引某个应用自己的窗口数组。标题发生变化、空白归一化或截断后，匹配失败就可能选错窗口。旧聚焦还吞掉 AXRaise 失败并返回成功。这是可从现有代码确认的问题。
2. **旧去重策略不够准确**：仓库已经存在按进程与标题去重的补丁，它能合并部分图形重复条目，也会误删真实同名窗口。用户当时“5→6、1→2”的具体应用、窗口状态和安装版本没有原样重现，不能把代码问题等同于已经证明该次现象的全部原因。
3. **本轮只读探测**：当前真实微信的图形表能看到两个有标题表面，AX 标准窗口列表为空；终端当前有一个有标题图形表面，AX 列表也为空。这里只能说明两种列表的含义不同，不据此断言用户当时究竟开了几扇窗口。没有读取聊天内容、真实账号配置或修改这些应用。

## 修复

- macOS 改为读取应用的 AX 标准窗口列表，以进程和窗口对象身份建立条目；不再把任意图形表面当作用户窗口。真实同名窗口分别保留。
- 扫描与聚焦使用同一种身份；查找消失、过期或不唯一时拒绝切换，不按标题、菜单或序号猜另一个窗口。实际抬起后校验前台应用与 AXFocusedWindow，避免“函数返回成功但打开的是 B”。
- 最小化目标先恢复再聚焦。较早的并发扫描不会覆盖较新的缓存。IPC 只接受工作区窗口调用与最近扫描缓存中的 ID。
- 读取窗口标题改用辅助功能属性，不再为了此功能探测或申请屏幕录制权限。底层读取方式参考 [Apple 的 AXUIElementCopyAttributeValue 文档](https://developer.apple.com/documentation/applicationservices/1462085-axuielementcopyattributevalue)。
- 切换或扫描失败进入持久错误栏并提供刷新重试，成功后清除对应错误；失败保留键盘目标，目标定位仅滚动窗口列表。窗口行和刷新/恢复按钮上的空格键激活控件，不会触发整块面板收起。
