# 首页铺满与已读按钮回归（2026-11-03）

在 `dev` 修复。已查看桌面 `111.png`、`222.png`、`333.jpg`，未修改原截图或读取用户工作区内容。下方截图来自隔离临时 userData、合成完成记录及窗口列表的生产 Electron 界面。

## 原因与修复

- 「全部已读」后追加了带自动左边距的监听状态，导致操作按钮停在标题与状态之间。现在标题占用剩余空间，监听状态排在按钮左侧，按钮保持最右侧；small 状态继续独立成行。
- 较小档虽然截断了可见集合，但固定网格仍保留空列、空行和不能利用的空格。现在先按原四档足迹取得紧凑逻辑排布，再只分配当前视图的剩余空间，保持统一卡片间距并铺满内容区。
- 容量仍按用户选择的 mini/small/medium/large 计算，仍严格按顺序截断；没有增加模块、修改字段/背景/字号方案，也不回写档位切换产生的显示矩形。
- 较小档的调整大小和拖动仅变更用户明确编辑的项目，不再为填满标准档的 12×4 存储画布而自动扩张其它模块的尺寸配置。标准档现有布局编辑行为保留。

## 验收路径

`tests/home-fill.electron.js` 复现用户截图中的顺序：番茄钟 small、随笔记 small、AI 完成提醒 medium、当前窗口 medium、AI 额度 medium。适中显示五项，逻辑占用 32/36；紧凑按序显示前四项，占用 24/24。

通过实际 DOM 边界检查卡片覆盖整个内容区、仅保留统一间距、没有矩形重叠和首页外滚；检查已读按钮位于标题行最右侧，监听状态在其左侧。覆盖标记已读、两档内调整卡片大小、紧凑拖动并保存、renderer reload，检查切档不改原存储偏好，拖动不改兄弟卡片尺寸。

`tests/panel-size.test.js` 额外覆盖截图配置、新默认集合、大卡片与单卡片的完整面积分配；逻辑足迹保持不变，显示矩形无越界、无交叠，归一化面积合计为 1。原 `panel-size.electron.js` 继续覆盖三档原生尺寸、四边停靠、弹层及重启恢复。
