# Pome 整体视觉与框架重构提案

状态：设计探索，尚未实施或选定方向。日期：2026-10-28。

## 这次要解决什么

让 Pome 的辨识度来自日常使用方式、首页的组织逻辑和一套完整视觉语言，而不是在原框架上换配色。

当前代码与实际 Electron 截图可确认：顶部仍是横向功能标签；首页仍将各类组件放在 Bento 网格里；待办保留分区容器；内容页已经统一了排版、列表和操作。上一轮工作台验收也明确保留了首页与窗口外壳。这解释了为什么细节更整齐后，整体轮廓仍然熟悉。

原项目公开 README 同样描述了横向页面、Bento 首页与分类待办。本提案据此判断共同的结构来源；并未对两款应用最新安装包进行逐像素比较，也不把主观相似感当成量化结论。

来源：[当前工作台验收](../../acceptance/2026-10-28-workbench/README.md)、[项目 README](../../../README.md)、[TO-DO-Panel 官方仓库](https://github.com/xiaopu-ai/TO-DO-Panel)。

## 共同的重构原则

1. 取消贯穿整个顶部的大胶囊功能导航。让内容本身成为窗口主体；顶边只承担当前区域、搜索和必要动作。
2. 首页有明确主次。先回答“我现在要做什么 / 接着做什么”，再提供一到两个辅助区域；不把所有能力等权铺开。
3. 任务以连续清单、分类索引或时间顺序呈现。现有 1–8 个分类保留，主视图不再固定为四块大分区。
4. 用字号、留白、对齐与少量分隔线建立层次。减少卡片嵌套、镜面高光、全局彩色描边和装饰背景图。
5. 给 Pome 定义自己的细节：稳定的品牌字标、内容位置标记、选中态和从边缘展开的节奏；它们应能贯穿首页、列表、编辑器、播放器、弹窗与通知。
6. 资料和工具仍能直接到达。视觉聚焦不能靠删除能力或把所有入口藏进菜单来实现。

## 三个结构不同的方向

以下名称用于设计说明。聊天中的选择编号以实际展示图片顺序为准。

| 方向 | 首页与导航 | 视觉系统 | 待办与其他页面如何延展 | 代价 |
| --- | --- | --- | --- | --- |
| 页间 | 像展开的一页工作札记；窄幅纵向索引；左侧今日清单为主、右侧续写笔记为辅 | 暖白、墨黑、少量石榴红；大标题、细分隔线、不等宽留白 | 待办为通栏分组清单，分类成为边缘索引；笔记为阅读页；链接和录音为资料目录 | 默认首页由自由拼块变成有主次的分区；浅色不应只套用旧深色透明层 |
| 流线 | “现在 / 资料 / 工具”三个主区域；首页是一条混合工作记录，按时间继续任务、笔记或 AI 完成事件 | 墨灰、灰白、少量低饱和青绿；时间刻度与内容行，而非发光仪表盘 | 待办按期限与分类切换；笔记、链接、录音共享清晰的索引；工具按需展开 | 需要把已有时间字段汇总成稳定视图；要区分创建、更新和截止，避免误导；实现成本相对最高 |
| 工作场 | 首页围绕当前一件事和番茄钟；其余待办在侧边排队；底部常驻简短工具带 | 浅雾绿、深松绿、少量暖橙；大号时间、规整线条和宽松间距 | 待办为一列主体与辅助详情；笔记/录音以侧页或完整内容页进入；资料库一层到达 | 专注感最强，但同时浏览多个组件的能力下降；必须做好工具可发现性与无专注任务的空状态 |

初步判断：如果首要目标是日常办公易用与品牌差异，优先考虑“页间”；如果经常在 AI、笔记与任务之间恢复上下文，可考虑“流线”；如果主要诉求是减少干扰，可考虑“工作场”。这是设计判断，需结合效果图和实际任务路径选择。

## 全页映射

| 区域 | 新的呈现原则 | 必须保留的能力 |
| --- | --- | --- |
| 首页 | 一个主要工作区、少量辅助信息；天气、黄历、音乐、镜子与额度进入可配置工具区域 | 模块显隐、平台可用性、至少一个有效模块；不把摄像头或麦克风自动启动 |
| 待办 | 清单为主，分类为索引或过滤；将截止时间和下一步动作做清楚 | 1–8 分类、顺序、编辑、截止、提醒、批选与同步语义 |
| 笔记 | 阅读和写作为主，列表退到侧边；避免内容上再包一层大卡片 | Markdown、搜索、改名、原文、自动保存、删除确认 |
| 链接 / 指令 | 紧凑目录、清楚的分组与复制动作 | 现有分组、编辑、复制、搜索与批量删除 |
| 录音 | 录音/播放状态和转写正文优先，工具控件低干扰 | 真实播放进度、音量、倍速、录制控制和音频释放 |
| 密钥 | 搜索、名称与账号为主；明文不出现在首页或混合记录中 | 系统加密、按需读取、复制、遮蔽、失败保护和删除确认 |
| 设置 | 单一索引与详情，按任务组织，不做另一张组件展示墙 | AI 接入、显示功能、本机行为、数据目录、NAS 等现有设置 |
| 删除确认 / 通知 | 跟随新字标、色彩、间距和状态样式 | 默认取消、键盘焦点、Esc、错误路径与不抢焦点通知 |

## 改造边界与兼容

- 本次可以彻底改变面板内部的首页、导航和页面布局；屏幕四边停靠、折叠胶囊、固定展开尺寸与多屏定位先沿用，避免把视觉重构与系统窗口重写耦合。
- 设计基准仍是 1240×638 的实际展开窗口。效果图按约 1.94:1 的宽高比表达，不能画一个很高的网页再声称可以原样放入面板。
- 保留 Electron / 原生 HTML、CSS、JavaScript；设计变化本身不构成换技术栈的理由。
- 首页“自由网格重排”如果改为“区域排序 / 工具显隐”，属于明确的体验变更。旧布局要留存、可回退，不能静默清空用户偏好；具体映射在选定方向后设计。
- 优先复用现有字段与数据服务。跨内容的恢复记录先做可重建投影，不在首轮引入项目关联、日历排程、协作或自动 AI 助手等额外产品功能。
- 本地数据、同步实体 ID、密钥边界和录制媒体所有权保持稳定。样式/布局偏好继续留在本机。
- 保留当前未提交工作。任何样式实施在方向选定后再开始；本轮只新增设计说明、参照截图与概念图。

## 实施顺序与退出条件

1. **当前这轮：选方向。** 三张独立首页概念图配合此计划，选择一种整体结构。概念图是生成的视觉草案，不是已运行的 Electron 界面。
2. **方向细化。** 补齐首页、待办、笔记、资料库、工具与通知/弹窗的关键状态；确定色彩、字号、间距、圆角、图标与明暗主题关系。先确认缩小到真实面板尺寸仍然读得清。
3. **做完整的一条路径。** 在现有桌面代码中实现新外壳 + 首页 + 待办；检验展开后添加一条待办、处理一条提醒、再回到当前内容，能否比现在更清楚。
4. **扩到内容与工具。** 按笔记 → 链接/指令 → 录音 → 密钥 → 设置推进。统一样式不等于强行统一页面结构，编辑器和播放器应有适合自身工作的布局。
5. **兼容与验收。** 相关单测、真实 Electron 截图、十语言长文案、窄屏、四边停靠、Esc/Space/焦点、减少动态效果、麦克风/摄像头释放与同步回归。Windows 真机和安装包另列实际完成情况。

不要一次性覆盖整个 renderer/styles.css 后再找回丢失的行为。先建立新主题与布局变量，分区域替换，确认同一路径的截图与行为合格后再撤旧样式。
